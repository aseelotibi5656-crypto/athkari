# أذكاري (Athkari)

تطبيق موبايل (iOS + Android) لمتابعة **أذكار الصباح والمساء** يوميًا، مع عدّاد
سلسلة الالتزام (Streak) الذي يشجّع على المداومة.

التطبيق **مجاني بالكامل — صدقة جارية**: بلا اشتراكات، بلا إعلانات، وبلا أي نظام دفع.

> صُنع بواسطة **أصيل العتيبي**

---

## المميزات

- **يعمل بدون إنترنت بالكامل** — نصوص الأذكار (٢٤ ذكرًا للصباح، ٢٣ للمساء من
  *حصن المسلم*) مخزّنة داخل التطبيق كملفات JSON، ولا يوجد أي طلب شبكة وقت
  التشغيل.
- **عدّاد سلسلة (Streak)** — اليوم يُحتسب فقط عند إنهاء **كل** أذكار الصباح
  **و** كل أذكار المساء في نفس اليوم بتوقيت الجهاز.
- **تذكيرات محلية** للصباح والمساء بأوقات مخصّصة، تعمل بدون إنترنت وحتى لو كان
  التطبيق مغلقًا، وتُعاد جدولتها تلقائيًا بعد إعادة تشغيل الجهاز.
- **تقويم شهري** يعرض الأيام المكتملة بنقاط خضراء، ويحتفظ بالسجل كاملًا حتى لو
  انكسرت السلسلة.
- **محلي بالكامل** — لا حسابات، ولا مزامنة سحابية، ولا تتبّع. بياناتك لا تغادر
  جهازك إطلاقًا، ولا يحتوي التطبيق أي حزمة تتصل بخادم خارجي.
- واجهة **عربية RTL** بالكامل، مع خطّي Almarai (الواجهة) و Amiri (نصوص الأذكار)
  مضمَّنين داخل التطبيق، ودعم الوضع الداكن.

## التشغيل السريع

### ١) تثبيت Flutter

حمّل Flutter من [flutter.dev](https://docs.flutter.dev/get-started/install)
وأضفه إلى `PATH`، ثم تأكّد:

```bash
flutter doctor
```

### ٢) إعداد المشروع

من داخل مجلد المشروع:

```bash
powershell -ExecutionPolicy Bypass -File tools\setup.ps1
```

السكربت يتحقّق من Flutter، ينزّل الحزم، ثم يشغّل التحليل والاختبارات.
مجلدا `android/` و`ios/` جاهزان في المشروع ولا يحتاجان توليدًا.

> بناء iOS يتم على خوادم GitHub (macOS) تلقائيًا — لا يلزم جهاز Mac.
> انظر قسم «البناء للنشر».

بدلًا من السكربت يمكنك يدويًا:

```bash
flutter pub get
```

### ٣) التشغيل

```bash
flutter run
```

## منطق الـ Streak

القاعدة الأساسية: **اليوم مكتمل فقط عند إنهاء كل أذكار الصباح وكل أذكار المساء
في نفس اليوم بتوقيت جهاز المستخدم المحلي.**

طريقة الحساب (في `lib/data/models/streak_model.dart`):

1. السلسلة **لا تُخزَّن كعدّاد**، بل تُشتقّ في كل مرة من سجلّ الأيام المكتملة.
   هذا يحميها من: تغيير ساعة الجهاز، إعادة تثبيت التطبيق، أو تعديل يوم قديم.
2. إذا كان **اليوم** مكتملًا → نعدّ رجوعًا بدءًا من اليوم.
3. وإلا، إذا كان **الأمس** مكتملًا → السلسلة ما زالت حيّة ونعدّ من الأمس
   (المستخدم أمامه بقية اليوم لإكمالها).
4. وإلا → صفر، لأن يومًا كاملًا فات بلا إكمال. وعندها تظهر رسالة
   **«ما عليك، ابدأ من جديد 🤍»** لا رسالة فشل.
5. سجلّ الأيام المكتملة (`history`) يبقى كاملًا دائمًا حتى لو انكسرت السلسلة،
   ليعرض التقويم الشهري التاريخ الحقيقي.

**حصانة التوقيت:** كل التواريخ تُطبَّع إلى منتصف الليل المحلي وتُخزَّن كنص
`yyyy-MM-dd` بلا معلومات منطقة زمنية، والفروق تُحسب على التواريخ المُطبَّعة —
فلا يؤثّر التوقيت الصيفي (يوم من ٢٣ أو ٢٥ ساعة) ولا السفر بين المناطق الزمنية
على العدّ.

الاختبارات في `test/streak_logic_test.dart` تغطّي: التتابع، الفجوات، حدود
الشهر والسنة، السنة الكبيسة، اختلاف ساعات اليوم، والمفاتيح التالفة.

```bash
flutter test
```

## البناء للنشر

```bash
flutter build apk --release        # أندرويد (APK)
flutter build appbundle --release  # أندرويد (Play Store)
flutter build ios --release        # iOS (على macOS فقط — أو عبر GitHub Actions)
```

يوجد بناء تلقائي على GitHub لكلتا المنصّتين:

| الملف | ماذا يفعل |
|---|---|
| `.github/workflows/android-build.yml` | يحلّل ويختبر ويبني APK جاهزًا للتحميل مع كل تعديل |
| `.github/workflows/ios-build.yml` | **verify:** يبني iOS بدون توقيع ويشغّله على محاكي iPhone ويلتقط صورة الشاشة (مع كل تعديل، بلا أسرار). **release:** يبني `.ipa` موقّعًا ويرفعه إلى TestFlight عند طلبه يدويًا أو عند دفع وسم `v*` |

### iOS بدون جهاز Mac

كل ما يحتاج macOS يعمل على خادم GitHub. إعدادات iOS في المشروع:

- Bundle ID: `com.aseelotibi.athkari` — اسم العرض: **أذكاري** — iPhone فقط، وضع رأسي
- الإصدار ورقم البناء يأتيان من `pubspec.yaml`، ورقم البناء يزيد تلقائيًا مع كل تشغيل على GitHub
- الأيقونات تُولَّد من `assets/icon/icon.png` عبر `dart run flutter_launcher_icons`
- شاشة الإقلاع بلون خلفية التطبيق (فاتح/داكن تلقائيًا) في `ios/Runner/Base.lproj/LaunchScreen.storyboard`

لتفعيل الرفع إلى TestFlight أضف الأسرار المذكورة في أعلى `ios-build.yml`
(شهادة التوزيع، ملف التزويد، ومفتاح App Store Connect API) في
Settings ← Secrets and variables ← Actions. لا تُحفظ أي شهادة أو مفتاح داخل المستودع.

قبل النشر على Google Play: أنشئ مفتاح توقيع خاصًا واستبدل `signingConfig`
المؤقّت في `android/app/build.gradle.kts` (يستخدم حاليًا مفتاح التصحيح ليعمل
`flutter run --release` مباشرة).

## مصدر النصوص

نصوص الأذكار مأخوذة من **حصن المسلم**، مع ذكر المرجع والفضل لكل ذكر داخل
التطبيق. الملفات في `lib/data/datasources/local/` ويمكن تعديلها أو التوسّع فيها
بنفس الصيغة:

```json
{
  "id": "morning_001",
  "title": "آية الكرسي",
  "text": "...",
  "repeat": 1,
  "reference": "سورة البقرة: ٢٥٥",
  "virtue": "..."
}
```
